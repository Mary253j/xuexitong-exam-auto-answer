# 学习通考试自动答题

Android 版本；安装后的应用名称为“题页助手”。

[下载 Android 1.0.12 安装包](downloads/quizhelper-1.0.12.apk) · [版本发布记录](https://github.com/Mary253j/-/releases/latest) · [发布前隐私检查](PRIVACY_REVIEW.md)

当前公开版本是 **1.0.12 网页答题复查版**，操作与数据处理见 [WEB_TESTING.md](WEB_TESTING.md)。1.0.10 的网页题干和选项读取已由用户真机确认；1.0.11 接入模型与选项操作；1.0.12 修复题目顺序改变、隐藏框架和单题题号保存问题，真实手机的模型调用和点击仍待测试，仍需手机实测。已有相同签名版本可以覆盖安装。模型功能需要在手机中手动填写自己的硅基流动 API Key，仓库和安装包不提供共享 Key。


这是针对本次需求新写的原生 Android App：启动后进入后台，每 5 秒读取学习通的无障碍文字，调用你准备的硅基流动 DeepSeek API，并选择返回的答案。它使用 Android 原生组件，不依赖 AutoX，不提供通用脚本执行功能。

**原 APP 的部分单题页面已确认缺少无障碍选项正文。网页版已在用户手机上成功登录，并读出十道题的题型、题干和完整选项。1.0.11 增加独立的“开始网页答题”和“停止网页答题”，保留原 APP 模式。** 网页模式无需无障碍授权；在主页保存 Key 和模型后打开官方网页，选择单题题号或本页多题，再开始。题页离开前台会停止，完成后手动核对并提交；网站本身可能随选项点击自动保存。需要 Android 8.0 或以上；没有原生架构库，适用于常见的 32 位、64 位 Android 手机。

## 安装和使用

1. 安装 `quizhelper-1.0.12.apk`，打开“题页助手”。与上一版使用相同包名和签名，可以覆盖更新。安装包是本次构建的本地签名版本，不是应用商店审核版本。
2. 阅读应用内的“权限与数据说明”，决定是否启用“题页助手”的无障碍服务。系统仍会显示无障碍敏感权限提示；独立开发不能消除这项权限本身的风险。
3. 填写 API Key、完整模型 ID，点击“保存 Key 和模型配置”。Key 会用 Android Keystore 管理的 AES-GCM 密钥加密后保存在本机应用私有数据中。返回助手、停止答题、进程重启都无需重新填写；卸载或清除应用数据会删除保存的配置。可以点击“测试 API 连接”，它会向模型发送一条简短测试题，验证连接和答案格式，不需要先开启学习通。
4. 选择页面模式：**单题模式**保留为默认选项，每次只处理最上方的一道完整题；**多题模式**依次处理当前页完整显示的题。你的章节测试连续列出多道题时，可选择多题模式。
5. 点击“只检测题目 · 不调用 API”，5 秒后读取学习通页面。检测不会调用 API 或点击答案。返回助手后，主界面只显示整理后的题干、选项和失败原因；原始节点信息默认折叠。检测结束后，仍需点击“开始自动答题”才会实际答题。
6. 点击“开始自动答题”，保持学习通题目页面在前台、亮屏且解锁。每 5 秒检查一次。逐题调用 API，并优先使用原生节点点击；页面没有提供原生点击操作时，按已核对的选项节点位置轻点。
7. 模型回复会显示在“模型答案”区域。如果你切回助手查看，答案会保留，回到对应题目后继续尝试选择，不会因为切回来就永久跳过该题或重复请求同一份答案。主界面保留“最近一次未完成的原因”，避免错误信息被“等待页面”覆盖。
8. 当前页完整题目处理完后，可手动切题或向下滚动。代码不会自动滚动，也不会点击下一题、提交或交卷。
9. “停止答题”会停止操作并释放运行中的 Key 引用，但保留加密保存的配置；“删除已保存的 Key”才会清除本机凭据。“停止并关闭无障碍服务”可以关闭系统授权状态，之后再次使用需要手动启用。

本版不会在开始或检测后清空 Key 输入框。配置界面仍以密码形式显示 Key。加密存储使用设备的 Android Keystore，不会降级为明文保存；解密或写入失败会提示重新输入。密钥是否由硬件保护取决于设备，不作统一保证。检测文字和模型答案仅保留在进程内存中。点击“复制问题反馈”才会将状态和检测信息复制到剪贴板；分享前请检查页面个人信息。反馈不会主动包含 Key。

本版为适配没有点击节点的 WebView，启用了无障碍的手势能力。如果覆盖安装后轻点操作未生效，可先在系统设置中关闭再启用“题页助手”的无障碍服务，使配置重新加载。仍然不使用截屏、录屏或分屏。

## 多选题与问答题

此前的“多选题无法读取选中状态”表示已识别文字，但程序因状态不明而跳过点击。本版先尝试从选项整行、原生复选框或系统提供的状态说明读取勾选状态；读得到时会选择正确项、取消已知错误项，并核对变化。

如果仍读不到状态，可以手动开启 **“多选状态读不到时，按空白题选择一次”**。这个开关默认关闭；开启前必须先取消学习通题目中已有的手动勾选。程序会按模型给出的答案逐项轻点，并把题目哈希、答案字母和点击状态保存在本机，避免切回程序或重启后又点一次、取消答案。它无法通过该模式确认最终实际选中状态，仍需你核对。

若中途退出导致点击状态无法确认，程序会停止该题并提示核对。新一轮重测、手动清空选项或需要重新尝试时，应先清空页面勾选，再点 **“重置多选点击记录”**，然后重新开始。重置仅清除这些记录，不删除 API Key。相同题干和选项会使用相同记录，即使出现在另一次测验中，也需按新一轮重测处理。

本版还支持有明确题型标记、可完整读取题干的 **简答题、问答题、论述题**。模型生成的参考答案会显示在“模型答案”中，点击 **“复制最新问答答案”** 后由你核对并粘贴到学习通。它不会自动填写、覆盖已有草稿或提交答案。多道问答题时也可长按答案区域选择需要的内容。缺少图片、材料或题目结束位置不明确时会跳过。

## 权限和网络行为

| 项目 | 实际实现 |
| --- | --- |
| 普通应用权限 | 清单仅请求 `android.permission.INTERNET` |
| 无障碍服务 | 服务通过 `BIND_ACCESSIBILITY_SERVICE` 保护，仅系统可绑定；用户需要手动启用 |
| 目标应用 | 无障碍事件筛选为 `com.chaoxing.mobile`；代码在遍历及读取文字前检查根节点与子节点包名 |
| 屏幕内容 | 读取无障碍文字，优先 `ACTION_CLICK`，必要时在核对后的节点中心轻点；`canTakeScreenshot=false`，`canPerformGestures=true` |
| 网络地址 | 模型请求固定为 `https://api.siliconflow.cn/v1/chat/completions`，不跟随重定向；网页测试另打开超星官方 HTTPS 站点，执行网站脚本 |
| 发送内容 | 解析出的题型、题干、选项；Key 用于该接口的认证请求头 |
| TLS | 系统证书校验，仅信任系统 CA；禁止明文 HTTP，没有自定义信任绕过 |
| 数据保存 | 模型名称和模式存本地；Key 经 AES-GCM 加密保存；另存多选题哈希和点击记录。网页模式的 Cookie 与站点存储由本机 WebView 保存，可手动清除；关闭备份，不导出完整页面 |
| 其他组件 | 网页测试新增 WebView，无 JavaScript 原生接口；无广告/统计 SDK、下载执行的原生代码、自动更新、开机启动接收器或内容提供器 |
| 未申请的权限 | 存储、通讯录、相机、麦克风、设备管理员、悬浮窗、屏幕捕获等 |

**上述包名与域名限制主要由这份代码落实，并非 Android 对无障碍能力和联网权限提供了严格的单应用、单域名沙盒。** 系统仍授予较强的无障碍能力。源码与本地检查有助于核对行为，不代表经过第三方安全审计或能够保证绝对安全。

自己的配置界面启用 `FLAG_SECURE`，用于避免 API Key 出现在最近任务预览和配置页截图中；应用没有截屏、录屏或分屏功能。

## 页面与答案限制

- 支持明确标注的单选、多选和判断题，包括 `1.[单选题]`。新版按节点的所属容器和位置组合字母与选项内容，支持字母和内容分别出现、节点读取顺序与屏幕排列不同的情况，不使用固定坐标或截图裁剪。
- 页面其他区域的标题、计时和提示不会按整页文字直接拼进选项。连续多题页面按每道题的题型标记和独立选项容器分组；单题和多题模式都保留。
- 无障碍树提供独立、完整显示的选项容器，或下一道题明确标记了本题的结束位置时，可以不依赖“下一题”等按钮。仅露出一部分的题目不会处理。
- 选择题选项需要文字完整、同列排列、全部显示在屏幕内。缺少原生点击操作时使用无障碍手势轻点；连位置或完整选项都无法确认时不操作。图片、Canvas、图片公式、缺少材料和填空题不在当前支持范围。
- 文字识别和点击能力分开判断：题目文字完整但无法可靠点击时，仍可显示模型答案及原因。多选状态读不到时默认仅显示答案，可按上方说明开启空白题模式。问答题仅生成参考答案并支持复制，不自动写入。
- 模型回复需要匹配题号、选项字母和选项原文。操作前重新读取题目并核对，节点文字和位置变化会取消点击。
- 已处理的题目不重复请求或点击。切换页面时保留已验证的模型答案，回到原题后再核对位置后选择。模型放弃或格式不匹配时跳过；停止后重新开始可重试。
- API 配置错误会停止，保留已保存的配置供修改；网络错误和限流会延后重试，最长 5 分钟。
- DeepSeek 对话接口提供模型推理，当前没有接入联网搜索或官方题库。它可能答错。
- 手机省电策略可能暂停后台服务；5 秒是运行期间的轮询间隔，不是系统休眠时的执行保证。应用不会主动保持亮屏、申请电池白名单或自动绕过系统限制。
- 代码没有隐藏自动化、绕过切屏检测或屏蔽安全提示的功能。

如果检测结果能看到题干和选项但无法解析，可根据文字调整 `Core.java`。若检测不到题目文字，在禁止截屏的条件下，当前方案无法识别它。

## 构建与验证

源码在 `app/src/main`，没有第三方运行依赖。`build.py` 直接使用 JDK、Android SDK 编译工具打包，不需要 Gradle 下载依赖。建议在 Linux、JDK 17+、Python 3、SDK Platform 35 和 Build Tools 35.0.1 下构建：

```sh
python3 build.py \
  --platform-jar /path/to/android-sdk/platforms/android-35/android.jar \
  --build-tools /path/to/android-sdk/build-tools/35.0.1
```

脚本会在本地 `.private/` 生成签名证书和密码文件；该目录不要提交或分享。源码包未包含本次 APK 的签名私钥。你自行构建会生成自己的签名，通常需要先卸载签名不同的旧版本再安装。

运行解析与权限检查：

```sh
mkdir -p test-out
java com.sun.tools.javac.Main -encoding UTF-8 -d test-out \
  app/src/main/java/cn/local/quizhelper/Core.java \
  app/src/main/java/cn/local/quizhelper/LayoutParser.java \
  app/src/main/java/cn/local/quizhelper/QuestionMode.java \
  app/src/main/java/cn/local/quizhelper/NodeTextPolicy.java \
  app/src/main/java/cn/local/quizhelper/SecretBox.java \
  app/src/main/java/cn/local/quizhelper/ToggleLedger.java \
  test/CoreTest.java test/LayoutTest.java test/RealLayoutTest.java test/SecretBoxTest.java test/MultiTextTest.java
java -cp test-out cn.local.quizhelper.CoreTest
java -cp test-out cn.local.quizhelper.LayoutTest
java -cp test-out cn.local.quizhelper.RealLayoutTest
java -cp test-out cn.local.quizhelper.SecretBoxTest
java -cp test-out cn.local.quizhelper.MultiTextTest
python3 test/check_permissions.py
```

这些检查验证核心解析、答案字段校验、多选状态处理、权限声明及固定 API 地址。除模拟布局外，`RealLayoutTest` 使用用户实际检测日志中的位置和节点路径构造回归数据，覆盖同屏两道完整题、第三道部分露出、大量屏幕外节点，以及两种模式。`SecretBoxTest` 在桌面加密提供者上验证保存恢复、随机 IV、篡改拒绝等；它不代表已在 Android Keystore 上实测。构建过程也验证 APK 签名与 ZIP 对齐。这些检查不替代真实手机上的 Key 恢复、手势轻点、后台运行和真实 API 调用测试。

参考：[Android 无障碍服务文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[Android Keystore 参数](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)、[硅基流动对话接口文档](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions)。
